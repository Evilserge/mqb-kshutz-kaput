## Поддерживаемое железо и форматы файлов

* **Блок управления:** передняя камера ассистентов водителя **Valeo MFK3** (`2Q0 980 653` с различными буквенными индексами), диагностический адрес **`0x00A5`**.
* **Аппаратная платформа:** хост-микроконтроллер **`Renesas RH850/P1H-C` (`R7F701372A`)** + видеопроцессор **`Mobileye EyeQ4`** (`DB_03`).
* **Версии прикладного ПО (`MEAPP`):** линейки **`13xx` / `14xx`**.
* **Поддерживаемые входные файлы:**
  * заводские зашифрованные контейнеры **`.frf`** и контейнеры **`.odx-f` / `.odx` / `.pdx`**;
  * отдельно извлечённый прикладной блок **`DB_01FLASHDATA.bin`** (`0x00048000..0x001FFFFF`, `~1.72 МиБ`);
  * полные дампы с программатора на столе: **`Bank 0` (`2 МиБ`)**, **`Dual-Bank` (`4 МиБ`)**, линейные дампы **`9.84 МиБ` / `10 МиБ`**.

## Что делает патчер в `Valeo MFK3`

### 1. Отключение защиты компонентов (`KS_PASSIVE`, 5 точек в `DB_01`)
* Переводит проверку `Komponentenschutz` в пассивный режим, снимая функциональную блокировку ассистентов на дооснащаемом автомобиле.
* Защищает блок энергонезависимой памяти **`NvM 0x3C`** от циклической перезаписи и износа счётчика ошибок CP.
* **Встроенные защиты от ошибок пользователя:**
  * проверяет и сохраняет неизменным 8-байтовый заголовок холодного старта (`0xAA000000` + `0x00048200` @ `0x00048000`);
  * автоматически блокирует попытку случайно пропатчить пакет обновления бутлодера **`0220_FBL`** (`~222 КБ`) под видом прикладной прошивки `MEAPP`.

### 2. Активация всех 9 кодов `FeC` / `SWaP` (4 точки в `DB_01`)
* Открывает все поддерживаемые прошивкой функции камеры в рантайме (по умолчанию включено; отключается флагом `--no-fecs`).
* Формирует полный заводской байт состояния **`0xFF`** во всех 9 слотах диагностического параметра **`DID 0x3C00`** (*Status of all SWaP functions* в `ODIS`: `Release code: available`, `Cancellation: no`, `Individualization characteristic: valid`, `Preconditions met: Condition met`, `Configuration: OK`, `Functions: available`, `Authentication: Condition met`):

| Код `FeC` | Назначение функции в `Valeo MFK3` |
| :---: | :--- |
| `100E0F00` | Распознавание дорожных знаков (**`VZE`** / *Traffic Sign Recognition*) |
| `100E1000` | Основные ассистенты водителя (**`Lane Assist`**, автодальний **`FLA`**, **`pACC`**) |
| `100E1100` | Расширенное ведение по полосе (*Extended Lane Guidance*) |
| `100E1200` | Дополнительный канал ассистентов водителя `#1` |
| `100E1300` | Дополнительный канал ассистентов водителя `#2` |
| `100E1400` | Дополнительный канал ассистентов водителя `#3` |
| `100E1500` | Дополнительный канал ассистентов водителя `#4` |
| `100E1600` | Резервный слот функций `#1` |
| `100E1700` | Резервный слот функций `#2` |

### 3. Подавление ошибок непривязанных ключей CP (`--suppress-key-dtcs`, опционально)
* Отключает фиксацию диагностических ошибок отсутствия базового/индивидуального ключей CP — актуально для абсолютно новых («чистых» *Virgin*) камер, в которых с завода ещё ни разу не проводилась привязка ключей.

### 4. Инженерная опция: `XCP` на шине `CAN0` (`--enable-xcp-can0`, по умолчанию ВЫКЛЮЧЕНА)
* **Обычным пользователям при ретрофите эта опция НЕ нужна.**
* Переводит `Xcp_BootControl` в активный режим `0x55` при старте камеры на шине **`CAN0`**:
  * разъём `T12a`: пин **`3 = CAN-H`**, пин **`4 = CAN-L`**, скорость **`500 кбит/с`**;
  * адресация `Extended 29-bit CAN`: запрос **`0x1BFE7E01`** → ответ **`0x1BFE7E00`**.

### 5. Безопасная сборка `ODX`-комплекта под `ODIS-E` (`PART1` + `PART2`)
* Прикладной блок `DB_01` упаковывается **строго без сжатия `LZSS A0` (`method=00`, `<SECURITY-METHOD>SIG_SHA1-RSA1024_S</SECURITY-METHOD>`)**, что исключает падение декодера загрузчика `0220` с ошибкой `7F 36 72` (`generalProgrammingFailure`) на перекрывающихся RLE-цепочках.
* Внутренние XML-идентификаторы сессий и областей памяти разделены (`_KS_FEC_PART1_S` и `_KS_FEC_PART2_S`), поэтому сервер `MCD-3D` в `ODIS-E` не конфликтует при одновременном добавлении обоих контейнеров в список прошивки.

## Двухэтапная прошивка через `ODIS-E` (`PART1` → `PART2`)

При сборке под `ODIS-E` скрипт создаёт две подпапки — `PART1` и `PART2`:

1. **Шаг 1 (`PART1`):** прошейте контейнер из папки `PART1`. В самом конце передачи, на проверке цифровой подписи (`RoutineControl 31 01 02 02`), `ODIS-E` ожидаемо покажет ошибку проверки подписи изменённого блока `DB_01` — **не пугайтесь и не выключайте зажигание**, пропатченное приложение уже записано во флеш-память камеры.
2. **Шаг 2 (`PART2`):** сразу следом, не выключая зажигание, прошейте контейнер из папки `PART2` (содержит родные заводские подписанные блоки `DB_30` + `DB_04`). Прошивка завершится на **100% зелёным** (`71 01 02 02 01`) и штатно выведет камеру из загрузчика в рабочий режим.

## Примеры CLI для `mfk3`

```bash
# Проверить контейнер (.frf / .odx-f) или дамп камеры
python3 ks_patcher.py -t mfk3 inspect FL_2Q0980653J_1423_MEAPP_V001_S.frf

# Собрать двухэтапный комплект PART1 + PART2 для ODIS-E (KS_PASSIVE + все 9 FeC)
python3 ks_patcher.py -t mfk3 patch FL_2Q0980653J_1423_MEAPP_V001_S.frf --build-odx ./ODIS_MFK3_READY

# Собрать ODX из сырого дампа DB_01 с указанием заводского шаблона .frf / .odx-f
python3 ks_patcher.py -t mfk3 patch DB_01FLASHDATA.bin --template-odx FL_2Q0980653J_1423_MEAPP_V001_S.frf --build-odx ./ODIS_MFK3_READY

# Пропатчить полный дамп программатора (Bank 0 / Dual-Bank) на столе
python3 ks_patcher.py -t mfk3 patch Bank0_dump.bin -o Bank0_patched.bin

# Побитово вернуть пропатченный дамп обратно в 100% заводской сток
python3 ks_patcher.py -t mfk3 patch Bank0_patched.bin --restore-stock -o Bank0_restored.bin
```
